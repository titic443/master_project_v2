## 1.1 ที่มาและความสำคัญของปัญหา

อุตสาหกรรมซอฟต์แวร์เติบโตอย่างรวดเร็ว ทำให้ Mobile Application มีความซับซ้อนสูงและเปลี่ยนแปลงบ่อย การประกันคุณภาพจึงต้องพึ่ง Test Case ที่ครอบคลุม

**ปัญหาหลักของการเขียน Test ใน Flutter:**

- นักพัฒนาต้องเขียน Test Script ด้วยภาษา **Dart** เองทั้งหมด
- ต้องอ่านโค้ดเพื่อทำความเข้าใจ **Validation Rules** ของแต่ละ Widget
- ต้องกำหนด **Input Data** (Valid / Invalid) ด้วยตนเอง
- ต้องจัดลำดับ **ขั้นตอน Test** ให้สอดคล้องกับ UI behavior
- หากขาดความละเอียดขั้นตอนใด กรณีทดสอบจะไม่ครอบคลุม

**ทำไม Tools อื่นไม่พอ:**

เครื่องมืออย่าง **Robot Framework** และ **Playwright** เป็นที่นิยมสำหรับ Web Testing แต่ยังไม่สามารถสร้าง Test Script สำหรับ **Flutter Framework** ได้โดยอัตโนมัติ

**แนวคิดที่นำมาต่อยอด (จาก Related Work):**

| งานวิจัย | แนวคิดที่นำมาใช้ |
|---|---|
| รัฐสรรค์ เอกอัครชวากิตติ์ [2] | การสกัด HTML Element และ Input Conditions จาก Frontend |
| พันทกานต์ ศรีวิชัยนันท์ [3] | Boundary Value Analysis สำหรับสร้าง Test Data จาก XSD |
| Tuan Pham [4] | Prompt Engineering (CO-STEP) เพื่อให้ LLM ตอบสนองได้ดีขึ้น |

**ข้อเสนอของงานวิจัยนี้:** สร้างกระบวนการอัตโนมัติที่:
1. สกัดข้อมูล Metadata จากไฟล์ Flutter Frontend
2. ใช้ LLM สร้าง Synthetic Test Data
3. ใช้ **Pairwise Testing Technique** สร้าง Test Cases อย่างเป็นระบบ
4. Output เป็น Dart Test Script พร้อม Run
